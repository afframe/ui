# C · IBM Products 2.99.0 catalog
Retrieved: 2026-09-24

## Summary (counts, what matters)

- `@carbon/ibm-products` 2.99.0 (npm latest, published 2026-09-16; `next`=2.99.0-rc.0) exports 151 names: 36 status-prefixed (`preview__` = 10, `previewCandidate__` = 26) and 115 unprefixed (legacy "stable"/canary via component flags). Source: `ibm-products-exports.json`.
- The package is mid-migration on two fronts at once: (1) a Product Development Lifecycle (PDLC) rename where many legacy stable components are marked `@deprecated` in JSDoc in favor of a `preview__`/`previewCandidate__` twin of the same name (e.g. `PageHeader` deprecated → `preview__PageHeader`; `Coachmark`/`CoachmarkBeacon` deprecated → `previewCandidate__Coachmark*`); and (2) a subset of components is being absorbed directly into `@carbon/react` core (v12 track), landing behind an `excludeProductsComponents` allowlist that is not yet published (verified in `@carbon/react` source, 2026-09-24: none of the 16 target names appear in `react-exports.json` yet).
- `Datagrid` and all its hooks are formally `@deprecated` (confirmed in source JSDoc and in a dedicated 2024-11-14 "datagrid deprecation notice" PR, ibm-products#6419, closing issue #6419→#6174). It is built on `react-table` v7.8.0 (dependency in package.json), which the project itself flagged as 5-years-stale in a still-open community ask (issue #4977, closed without a shipped replacement) to migrate to TanStack Table v8. No successor Datagrid has shipped.
- The `examples/carbon-for-ibm-products/*` directory has 56 per-component CodeSandbox/Stackblitz-ready example apps plus a gallery and framework-version smoke-test apps (react-16/17 examples), confirming React-only orientation already decided for Afframe UI.
- The repo ships four packages: `ibm-products` (React, the one in scope), `ibm-products-styles` (Sass/CSS, a real peer dependency), `ibm-products-utilities` (small shared JS helpers), and `ibm-products-web-components` (Lit/Web Components — out of scope per the React-only decision).

## Datagrid (status, deprecation, replacement)

- `Datagrid` (the component) carries `@deprecated` directly in its JSDoc in `packages/ibm-products/src/components/Datagrid/Datagrid/Datagrid.tsx` (confirmed in the built `lib/components/Datagrid/Datagrid/Datagrid.js` of the unpacked 2.99.0 package).
- ibm-products#6419 "chore: datagrid deprecation notice" (merged 2024-11-14) added the deprecation notice to `Datagrid.mdx`, `Datagrid.docs-page.js`, and `.deprecated` metadata across the Datagrid stories/tests, closing tracking issue #6174 "Update Storybook to show deprecation (Datagrid)". Source: `gh api repos/carbon-design-system/ibm-products/pulls/6419`.
- Root cause: `Datagrid` and all its `use*` hooks (`useDatagrid`, `useNestedRows`, `useInlineEdit`, `useFiltering`, etc.) are built on `react-table` v7.8.0, pinned as a runtime `dependency` in `@carbon/ibm-products` 2.99.0's `package.json`. Issue #4977 "Upgrade to React table v8 - v7 has had no meaningful updates for 5 years" (closed 2024-11-25, without a shipped migration) explicitly requested a TanStack Table v8 rewrite; no replacement component has shipped as of 2.99.0.
- No successor grid ships from ibm-products itself in this release; teams building on it are consuming a frozen, deprecated API surface (26 exports: `Datagrid` + 21 hooks + `getAutoSizedColumnWidth` + `useFilterContext`).
- Implication for Afframe UI: treat Datagrid as `reference` only (patterns to study — column customization, nested rows, filtering panel wiring), not as the data-table foundation; a production data grid should be built on Carbon core `DataTable` or a maintained third-party table library (TanStack Table v8, etc.) instead.

## Setup: peers, flags, styles

- **Peer dependencies** (from unpacked 2.99.0 `package.json`): `@carbon/grid ^11.61.0`, `@carbon/layout ^11.58.0`, `@carbon/motion ^11.51.0`, `@carbon/react ^1.115.0`, `@carbon/themes ^11.80.0`, `@carbon/type ^11.66.0`, `react ^16.8.6 || ^17.0.1 || ^18.2.0 || ^19.0.0`, `react-dom` (same range), `react-is` (same range). Runtime `dependencies` include `@carbon/feature-flags ^1.8.0`, `@carbon/ibm-products-styles ^2.95.0`, `@carbon-labs/react-resizer ^0.25.0`, `@dnd-kit/*`, `react-table ^7.8.0` (Datagrid, deprecated), `react-window ^1.8.11`.
- **Styles**: import `@carbon/ibm-products/css/index.min.css`, or use the Sass entry points (`@use '@carbon/ibm-products/scss'` for everything, or per-component `@use '@carbon/ibm-products/scss/components/<Name>'` plus `@use '@carbon/ibm-products/scss/config'`). Styles ship from the separate `@carbon/ibm-products-styles` package (2.95.0 pinned as of this ibm-products release; note the version lag vs the 2.99.0 `ibm-products` package itself).
- **Prefix**: default CSS/JS selector prefix is `c4p`, changeable globally via `pkg.prefix = '...'` (JS) before first render, and via the Sass `$pkg-prefix` variable (must match on both sides).
- **Component enablement (feature flags)**: `@carbon/ibm-products` uses a "canary" component-flag mechanism (`pkg.component.<Name> = true/false` from `@carbon/ibm-products/es/settings` or root `pkg` export) to gate components that "have not completed their review process." Defaults are baked into `package-settings.js`; e.g. `AboutModal`, `CreateModal`, `CreateTearsheet*`, `Datagrid`, `EmptyState`, `ExportModal`, `FullPageError`, `HTTPError*`, `ImportModal`, `NotificationsPanel`, `PageHeader`, `ProductiveCard/ExpressiveCard`, `RemoveModal`, `Saving`, `SidePanel`, `TagSet`, `Tearsheet(Narrow)`, `UserProfileImage/UserAvatar`, `WebTerminal*`, `InterstitialScreen` are enabled by default; `Toolbar*`, `EditSidePanel`, `DataSpreadsheet`, `EditTearsheet*`, `EditFullPage`, `EditUpdateCards`, `Nav*`, `BigNumber`, `TruncatedList/Text`, `DelimitedList`, `ScrollGradient`, `StringFormatter`, `StatusIndicator(Step)`, `TagOverflow`, `ActionBar`, `FilterPanel*`, `ConditionBuilder`, `GetStartedCard`, `Card*`, `Coachmark*`, `Decorator*`, `DescriptionList*`, `SearchBar`, `EmptyStateV2`, `Guidebanner*`, `InlineTip*`, `NonLinearReading` are **off by default** (require `pkg.component.X = true` or `pkg.setAllComponents(true)`). Source: `lib/global/js/package-settings.js` (unpacked 2.99.0).
- **The component-flag mechanism itself is deprecated**: `package-settings.js` embeds a hardcoded warning: "The component feature flag (canary) mechanism is deprecated and will be removed in a future release. Components are now published with a PDLC status prefix and can be imported directly, e.g. `import { previewCandidate__ComponentName } from "@carbon/ibm-products"`." (verbatim, retrieved from `lib/global/js/package-settings.js`). This confirms the exported `preview__`/`previewCandidate__`-prefixed names are the intended forward path, replacing the old boolean-flag canary system used by the 115 unprefixed exports.
- **Separate feature flags** (distinct from component flags): `pkg.feature['Datagrid.useInlineEdit']`, `Datagrid.useEditableCell`, `Datagrid.useCustomizeColumns`, plus a `default-portal-target-body` flag (on by default), all set via `pkg.feature.<name> = true`.
- **Webpack 4** needs an explicit rule for `.mjs` files under `node_modules` since the package ships ES modules; Webpack 5 handles this by default (per README).
- **Web Components package** (`@carbon/ibm-products-web-components`, Lit-based) exists as a parallel implementation with its own `src/patterns/*.mdx` docs (api-key-modal, coachmark variants, create-full-page/modal/side-panel/tearsheet, delete-and-remove, export-modal, saving) but is out of scope given the React-only decision.
