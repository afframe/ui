## Still open

- Whether the package's inherited permissions from `afframe/ui` must be removed before "Manage Actions access" can add other repos. The docs say inheritance must be removed to reach "granular permissions settings" ("If you want to configure a package's access settings on a granular level, separately from the linked repository, you must remove the inherited permissions from the package."), but the Manage Actions access steps do not mention it.
- Whether a consumer workflow's `GITHUB_TOKEN` can install a **public** org-scoped npm package without an explicit Manage Actions access grant. The docs require an explicit grant for workflow access and say nothing specific about public packages. Also the exact `permissions:` key the consumer job needs (e.g. `packages: read`), which was not found in the pages read.
- Whether npm trusted publishing is supported for restricted/private packages (stated only indirectly) and whether a manual `--provenance` publish of a private package succeeds.
- Trusted publishing / npm provenance on GitHub Packages (npm.pkg.github.com): no documentation found either way.
- The npmjs.com/products pricing page returned HTTP 403, so the $7 figures come from docs.npmjs.com, not the live pricing page.
- Contradiction inside GitHub docs: about-push-protection says repository push protection "Requires GitHub Secret Protection to be enabled", while the features page and the GHAS table list it as free for public repos. The enablement UI was not observed.
- Contradiction inside GitHub docs on dependency review: the features page says "Available for public repositories by default"; the GHAS table shows "No" for public repos without Code Security.
- Trademark status of "Carbon" / "Carbon Design System" (not on IBM's list; no Carbon-specific guidance found).
- Whether a CSS `font-family` alias for a self-subset Plex counts as the "primary font name as presented to the users" under OFL condition 3. The SIL OFL FAQ was not consulted.
- Legal effect of combining Apache-2.0 (Carbon-derived) and PolyForm NC code in one package, beyond what the license texts state.
- claude-code-action runtime behaviour when `CLAUDE_CODE_OAUTH_TOKEN` is empty on fork PRs (error vs skip) was not observed.
- pnpm and yarn behaviour for git dependencies with a `prepare` script.
