# Feature flags

Afframe UI runs stable Carbon v11 with the v12 flags on (ADR 0002). Carbon flags have two sides, and both must be set:

- React: `AfframeProvider` renders Carbon's `<FeatureFlags>` around the app.
- Sass: the styles build sets `$feature-flags` before Carbon's styles load. Styling changes come only from Sass.

Consumers set nothing; `AfframeProvider` and `styles.css` carry the flags.

## On

| Flag                            | Why                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `enable-v12-release`            | v12 behaviour and look. Also turns on `enable-v12-tile-default-icons`, `enable-v12-tile-radio-icons`, `enable-v12-overflowmenu`, `enable-v12-structured-list-visible-icons`, `enable-v12-dynamic-floating-styles`, `enable-v12-toggle-reduced-label-spacing` and `enable-focus-wrap-without-sentinels`                                                                                                                                                                                                                                                    |
| `enable-dialog-element`         | opt-in, not part of v12. Carbon `Modal` and `ComposedModal` render a native `dialog` element, which makes the page behind inert. CreateModal, EditTearsheet (through IBM's Tearsheet), the discard dialog of the create and edit components, RemoveModal, ImportModal, ExportModal and APIKeyModal are built and tested with it on. Under it Carbon skips `selectorPrimaryFocus`, so they set initial focus themselves; CreateModal, EditTearsheet and the discard dialog also wrap Tab themselves, because Chromium lets Tab leave a native modal dialog |
| `enable-presence`               | opt-in, not part of v12                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `enable-enhanced-file-uploader` | opt-in, not part of v12                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `enable-treeview-controllable`  | opt-in, not part of v12                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `enable-tile-contrast`          | opt-in, not part of v12                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |

Carbon's own flag reference: https://github.com/carbon-design-system/carbon/blob/main/docs/feature-flags.md

## Rules

- Never render a `<feature-flags>` DOM element above `@carbon/ai-chat`: its overflow menus stop opening (carbon-ai-chat issue #2308). The chat keeps the v11 look until it supports v12.
- `enable-v12-release` turns on `enable-focus-wrap-without-sentinels` and `AfframeProvider` turns on `enable-dialog-element`. With the dialog element the focus wrap flag has no effect on `Modal` and `ComposedModal`, so both log a development-only warning that the two flags are on. It is harmless and stays: `ActionableNotification` (not a dialog) uses the flag for its Tab wrap, and turning it off would bring back its two tabbable focus sentinels.
- IBM Products' own rules (`.c4p--`) do not change under the v12 flag; Carbon elements inside IBM Products components get v12 styling from the same build (Sass compile check, 2026-09-24).
- IBM Products components behind its canary setting (in 2.100.0: ScrollGradient and `previewCandidate__Decorator`) are enabled when the `AfframeProvider` module loads, with IBM's warnings silenced, not by consumers. An app that never imports that module gets IBM's placeholder for these two.
- IBM Products' own flag API is re-exported as `preview__FeatureFlags`, `preview__useFeatureFlag` and `preview__useFeatureFlags`; for example, SidePanel reads `enableSidepanelResizer` from it.

## Known v12 breaks

| Component                                                                                 | Break                                                                                                                                                                                                                                                                                       | Handling                                                                                                                                                                                     |
| ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `OverflowMenu` with `OverflowMenuItem` children, including DataTable `TableToolbarAction` | items cannot be reached or activated by keyboard under `enable-v12-overflowmenu` in `@carbon/react` 1.117.0: the v12 menu only focuses items registered with it, and `OverflowMenuItem` never registers; fixed on Carbon main (PR #23375), not yet in a stable release (checked 2026-10-05) | `MenuItem` children (with `label` on `OverflowMenu` or `TableToolbarMenu`); `OverflowMenuItem` stays exported with v11 behaviour; drop the workaround when a stable release contains the fix |

Add a row when v12 breaks a component Afframe needs, with the evidence and the handling.

## Story exceptions

Every story runs the a11y check as an error under the v12 flags. A known upstream violation is switched off for that story only, by axe rule id in `parameters.a11y.config.rules` (`docs/testing.md`), and gets a row here. A story that needs a flag changed sets it locally with a `FeatureFlags` decorator and gets a row here too. Afframe-owned stories (tag `afframe`) also run axe's `target-size` rule and take no exceptions (`docs/testing.md`).
