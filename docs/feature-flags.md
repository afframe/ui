# Feature flags

Afframe UI runs stable Carbon v11 with the v12 flags off except `enable-focus-wrap-without-sentinels`, plus a few opt-in flags (ADR 0018). Carbon flags have two sides, and both must be set where Carbon reads the flag on that side:

- React: `AfframeProvider` renders Carbon's `<FeatureFlags>` around the app.
- Sass: the styles build sets `$feature-flags` before Carbon's styles load. Styling changes come only from Sass.

Consumers set nothing; `AfframeProvider` and `styles.css` carry the flags.

## On

| Flag                                  | Why                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `enable-dialog-element`               | opt-in. Carbon `Modal` and `ComposedModal` render a native `dialog` element, which makes the page behind inert. CreateModal, EditTearsheet (through IBM's Tearsheet), the discard dialog of the create and edit components, RemoveModal, ImportModal, ExportModal and APIKeyModal are built and tested with it on. Under it Carbon skips `selectorPrimaryFocus`, so they set initial focus themselves; CreateModal, EditTearsheet and the discard dialog also wrap Tab themselves, because Chromium lets Tab leave a native modal dialog; IBM's AboutModal does not, so Tab from its last link leaves it (AboutModal page, `withAdditionalContent` play test) |
| `enable-focus-wrap-without-sentinels` | React only (Carbon's Sass never reads it). Carbon groups it with v12, but it changes no look. `ActionableNotification` wraps Tab without two tabbable focus sentinels. No effect on `Modal` and `ComposedModal` under `enable-dialog-element`, which log a harmless development warning that both flags are on                                                                                                                                                                                                                                                                                                                                                |
| `enable-presence`                     | opt-in                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `enable-enhanced-file-uploader`       | opt-in                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `enable-treeview-controllable`        | opt-in                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `enable-tile-contrast`                | opt-in                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |

Carbon's own flag reference: https://github.com/carbon-design-system/carbon/blob/main/docs/feature-flags.md

## Rules

- Never render a `<feature-flags>` DOM element above `@carbon/ai-chat`: its overflow menus stop opening (carbon-ai-chat issue #2308).
- `LogoutBanner` also sets `enable-focus-wrap-without-sentinels` locally, so it works without the provider.
- `enable-v12-dynamic-floating-styles` stays off: it drops `flip` from MenuButton and ComboButton, so their menus open past the bottom of the screen (browser check, 2026-10-12). It does not change the look. A floating element clipped by a scroll container gets `autoAlign` on that one instance.
- `enable-v12-overflowmenu` stays off globally. The Afframe `OverflowMenu` and `TableToolbarMenu` turn it on for one menu when the caller passes `label` or `MenuItem` children (the 1.0.1 shape): only Carbon's newer menu works with them by keyboard. The flag changes no look, because Carbon gates the v12 menu look on `enable-v12-release`. Carbon's internal menus (IBM Products, `DataGrid`) are not affected.
- IBM Products components behind its canary setting (in 2.100.0: ScrollGradient and `previewCandidate__Decorator`) are enabled when the `AfframeProvider` module loads, with IBM's warnings silenced, not by consumers. An app that never imports that module gets IBM's placeholder for these two.
- IBM Products' own flag API is re-exported as `preview__FeatureFlags`, `preview__useFeatureFlag` and `preview__useFeatureFlags`; for example, SidePanel reads `enableSidepanelResizer` from it.

## Story exceptions

Every story runs the a11y check as an error under the flags above. A known upstream violation is switched off for that story only, by axe rule id in `parameters.a11y.config.rules` (`docs/testing.md`), and gets a row here. A story tagged `!test` does not run as a test and gets a row here. A story that needs a flag changed sets it locally with a `FeatureFlags` decorator and gets a row here too. Afframe-owned stories (tag `afframe`) also run axe's `target-size` rule and take no exceptions (`docs/testing.md`).
