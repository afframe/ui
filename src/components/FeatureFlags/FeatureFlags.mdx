# Feature flags

<SourceLabel name="afframe" />

Afframe UI runs Carbon v11 with the v12 feature flags off except the focus
wrap flag, and a few opt-in flags on. Consumers set nothing:
`AfframeProvider` turns the flags on in React and `styles.css` is built with
their Sass side; the two lists differ where Carbon reads a flag on one side
only (`docs/feature-flags.md`).

## React flags

`AfframeProvider` wraps the app in Carbon's `FeatureFlags` with:

- `enableDialogElement`
- `enableFocusWrapWithoutSentinels` (React only)
- `enablePresence`
- `enableEnhancedFileUploader`
- `enableTreeviewControllable`

## Sass flags

`styles.css` is compiled with:

- `enable-dialog-element`
- `enable-presence`
- `enable-enhanced-file-uploader`
- `enable-treeview-controllable`
- `enable-tile-contrast` (Sass only: Carbon React never reads it)

## IBM Products flags

IBM Products has its own flag API, separate from Carbon's, exported as
`preview__FeatureFlags` with the hooks `preview__useFeatureFlag(name)` (one
flag, a boolean) and `preview__useFeatureFlags()` (the flag scope, read with
`.enabled(name)`). Afframe sets none of them. Two matter for the exported
components:

- `defaultPortalTargetBody`, on by IBM's default: `AboutModal` and the
  overflow modal of `TagSet` render into `document.body`.
- `enableSidepanelResizer`, off: turn it on to let the user resize a
  `SidePanel`.

```tsx
import {
  preview__FeatureFlags as IbmFeatureFlags,
  SidePanel,
} from '@afframe/ui';

<IbmFeatureFlags enableSidepanelResizer>
  <SidePanel>…</SidePanel>
</IbmFeatureFlags>;
```

IBM's other flags (`enableDatagridUse*`) belong to IBM's Datagrid, which Afframe
UI does not export; use `DataGrid` instead.
