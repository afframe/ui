# EditTearsheet

<SourceLabel name="afframe" />

[Source code](https://github.com/afframe/ui/tree/main/src/components/EditTearsheet). See also [Forms pattern](https://carbondesignsystem.com/building-blocks/core/patterns/forms).

`EditTearsheet` edits a record with several forms in IBM Products' tearsheet
(`preview__Tearsheet`), laid out as IBM Products' deprecated EditTearsheet,
which it replaces: a side navigation lists the forms and shows one at a time.
The other forms stay mounted, hidden, so their values survive switching. The
actions, ghost Cancel and primary Save, sit under the form column; the
navigation runs the full height on the left. It shares its submit, cancel,
discard and focus behaviour with `CreateModal`, `CreateSidePanel`,
`EditSidePanel` and `EditFullPage`.

<Canvas of={EditTearsheetStories.Default} />

## Which component to use

Use `EditTearsheet` when an edit has several forms the user moves between.
One form that fits a panel is an `EditSidePanel`; a long single form that
needs the page is an `EditFullPage`.

## Usage and props

`open` is controlled. The children are `EditTearsheetForm` elements, each one
section with its own heading. `onSubmit` may return a promise: while it is
pending Save is disabled; when it resolves, `onClose` is called; when it
rejects, the tearsheet stays open and shows the error under the shown form.
Closing while it is pending asks first, unless `confirmDiscard` is false:
"Discard changes?" on a dirty form, "Stop waiting?" on a clean one. Discard or
Stop waiting closes the tearsheet and ignores the result; the dialog closes
itself when the promise settles. If it is still shown or opened again before
then, it stays busy until it settles.

```tsx
import { EditTearsheet, EditTearsheetForm } from '@afframe/ui';

const launcherRef = useRef<HTMLButtonElement>(null);
const [open, setOpen] = useState(false);
const [name, setName] = useState(customer.name);
const [vat, setVat] = useState(customer.vat);

<Button ref={launcherRef} onClick={() => setOpen(true)}>
  Edit
</Button>
<EditTearsheet
  open={open}
  onClose={() => setOpen(false)}
  onSubmit={() => api.updateCustomer(customer.id, { name, vat })}
  launcherRef={launcherRef}
  label="Customer"
  title={customer.name}
  isDirty={name !== customer.name || vat !== customer.vat}>
  <EditTearsheetForm id="contact" title="Contact">
    <TextInput id="name" labelText="Name" value={name} onChange={...} />
  </EditTearsheetForm>
  <EditTearsheetForm id="billing" title="Billing" invalid={!isVat(vat)}>
    <TextInput id="vat" labelText="VAT number" value={vat} onChange={...} />
  </EditTearsheetForm>
</EditTearsheet>;
```

- `title`, `label` (above the title) and `description` head the tearsheet.
  The close icon stays, as in IBM's tearsheet.
- `variant`: `wide` (default) or `narrow` (480px). In `narrow`, and below the
  `md` breakpoint, the navigation moves into IBM's side panel, opened by an
  icon button above the form; choosing a form closes the panel.
- `headerActions`: IBM's `Tearsheet.HeaderActions` with
  `Tearsheet.HeaderActionItem`s (both from `@afframe/ui`'s `Tearsheet`),
  beside the title; they collapse into a menu button when space runs out.
- `decorator`: an `AILabel` or another decorator in the header.
- `influencerWidth`: `narrow` (default, 16rem) or `wide` (20rem) side
  navigation.
- `onFormChange(index)`: called when a form is chosen in the navigation.
- Only `EditTearsheetForm` children are rendered; other children are left
  out with a console warning.
- `EditTearsheetForm`: `id` (unique in the page), `title` (a level 3
  heading), `description`, `invalid`. Its fields take 8 of the 16 grid
  columns from `lg` up (all of them in `narrow`), stacked.
- `invalid` marks the form's navigation item with an error icon. Save stays
  enabled; while a form is invalid, Save does not submit: it shows the first
  invalid form and moves focus to its heading instead.
- `isDirty`: compare the field state with the saved values. When true,
  Escape, the close icon and Cancel ask "Discard changes?" first, unless
  `confirmDiscard` is false. An overlay click never closes the tearsheet.
- `submitDisabled`: disables Save and Enter.
- `launcherRef`: where focus goes on close. Without it, or when it is gone,
  focus returns to the element that had focus when the tearsheet opened.
- `ref` and any other HTML attributes (`id`, `data-*`, `style`) go to the
  tearsheet's root `div` (Carbon ComposedModal's, portaled to `body`), where
  `className` lands too. IBM names the dialog itself. The ref is `null` while
  the tearsheet is closed; the discard dialog renders beside it, never inside.

## Differences from IBM's EditTearsheet

- Navigation items are links to the form ids, so Tab reaches them; IBM's
  have no `href`. A modified or middle click is left to the browser.
- Form titles are level 3 headings, under the tearsheet's level 2 title;
  IBM's are level 4, which skips a level. They look the same.
- Fields go straight into `EditTearsheetForm`; it places them in a Carbon
  `Column` itself, where IBM expects your own.
- In the side panel, choosing a form closes the panel and Escape closes only
  the panel, so the shown form is never left covered.
- The dirty check, discard dialog, error alert, busy Save and invalid-form
  marker are Afframe's shared flow, which IBM's component does not have.

## Messages

`messages?: Partial<EditTearsheetMessages>`; defaults in
`defaultEditTearsheetMessages`. `sectionInvalid` and the optional `errorText` are functions: override them
from a client component (server components can pass only the string keys).

| Key                    | Default                                                     |
| ---------------------- | ----------------------------------------------------------- |
| `save`                 | Save                                                        |
| `cancel`               | Cancel                                                      |
| `sectionsNavLabel`     | Sections                                                    |
| `sectionInvalid`       | `title` has errors                                          |
| `openSections`         | Open sections                                               |
| `pending`              | Saving                                                      |
| `error`                | The changes could not be saved. Try again.                  |
| `errorText`            | not set: `error` is shown                                   |
| `errorIconDescription` | Error                                                       |
| `discardTitle`         | Discard changes?                                            |
| `discardBody`          | Your changes will be lost.                                  |
| `discard`              | Discard                                                     |
| `keepEditing`          | Keep editing                                                |
| `leavePendingTitle`    | Stop waiting? (closing a clean form while it saves)         |
| `leavePendingBody`     | Saving continues in the background.                         |
| `leavePending`         | Stop waiting                                                |
| `keepWaiting`          | Keep waiting                                                |
| `closeIconDescription` | Close (the tearsheet's and the discard dialog's close icon) |

## Keyboard and screen reader behaviour

On open, focus moves to the first control of the first form. Focus order: the
close icon, the header actions, the navigation items, the open-sections button
(narrow and small screens), the shown form's fields, Cancel, Save. Hidden
forms are out of the focus order. Tab and Shift+Tab stay inside the tearsheet
and wrap.

| Key    | Where                 | Action                                                                                                                                                  |
| ------ | --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Enter  | navigation item       | Shows that form; focus stays on the item. In the side panel (narrow and small screens), the panel closes and focus returns to the open-sections button. |
| Escape | navigation side panel | Closes only the panel; focus returns to the open-sections button.                                                                                       |
| Enter  | single-line field     | Submits once, unless `submitDisabled` or a submit is pending. Not in a multi-line field.                                                                |
| Escape | anywhere in the sheet | Closes a clean tearsheet. On a dirty one, or while a submit is pending, opens the discard dialog.                                                       |
| Escape | discard dialog        | Closes only the discard dialog; focus returns to the element that had it.                                                                               |
| Tab    | discard dialog        | Moves between its close icon, Keep editing and Discard; focus starts on Keep editing.                                                                   |

On close, focus returns to `launcherRef`, else to the element that had focus
when the tearsheet opened, else to the page body.

A focused field never sits under the sticky footer: fields keep a scroll
margin the size of the footer (the test-only `FocusNotObscured` story checks it).

Screen readers announce:

- the tearsheet as a dialog named by its title; the navigation as a landmark
  named `sectionsNavLabel`, its items as links, the shown form's item with
  `aria-current`; an invalid form's error icon as an image named
  `sectionInvalid(title)`;
- the shown form as a region named by its heading;
- while saving, the form as busy and `pending` in a polite status; Save keeps
  its name and shows a spinner;
- a rejected submit as an alert with `error` (or `errorText(error)`). Focus
  moves to the first field with `aria-invalid="true"` in the shown form, else
  to the first one in a hidden form, showing that form first (also when the
  field is marked a render after the error, unless a form was chosen in the
  meantime), else to the alert;
- the discard dialog as an alert dialog named by `discardTitle`, described by
  `discardBody` (`leavePendingTitle` and `leavePendingBody` on a clean form
  while it saves).
