## Accessibility Considerations

### Accessible Name

`labelText` renders a visible label tied to the input, which gives the field
its accessible name. Keep interactive content such as a toggletip outside
`labelText`, as the With Toggletip story does.

### Error message and screen readers

FluidTextInput renders Carbon's TextInput, so it has the same gap: while
`invalid`, the input points `aria-errormessage` at its error text, but nothing
announces that text and axe reports `aria-valid-attr-value`. Pass the error id
while `invalid` is set; Carbon renders it as `<id>-error-msg` and keeps your
`aria-describedby`:

```tsx
<FluidTextInput
  id="company-name"
  labelText="Company name"
  invalid={invalid}
  invalidText="Enter a company name."
  {...(invalid && { 'aria-describedby': 'company-name-error-msg' })}
/>
```

The same applies to FluidPasswordInput. A warning is linked by Carbon already.
