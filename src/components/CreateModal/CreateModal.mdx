# CreateModal

<SourceLabel name="afframe" />

[Source code](https://github.com/afframe/ui/tree/main/src/components/CreateModal). See also [Create flows pattern](https://ibm-products.carbondesignsystem.com/?path=/docs/patterns-create-flows-create-modal--overview).

`CreateModal` is a small create form (one to three fields) in a Carbon
`Modal`. It replaces IBM Products' deprecated CreateModal. It shares its
submit, cancel, discard and focus behaviour with `CreateSidePanel`,
`EditSidePanel`, `EditTearsheet` and `EditFullPage`.

## Usage and props

`open` is controlled. `onSubmit` may return a promise: while it is pending the
primary button is disabled and shows Carbon's inline loading; when it resolves, `onClose` is
called; when it rejects, the modal stays open and shows the error. Closing while
it is pending asks first, unless `confirmDiscard` is false: "Discard changes?"
on a dirty form, "Stop waiting?" on a clean one. Discard or Stop waiting closes
the modal and ignores the result; the dialog closes itself when the promise
settles. If it is still shown or opened again before then, it stays busy until
it settles.

```tsx
import { CreateModal } from '@afframe/ui';

const launcherRef = useRef<HTMLButtonElement>(null);
const [open, setOpen] = useState(false);
const [name, setName] = useState('');

<Button ref={launcherRef} onClick={() => setOpen(true)}>
  New customer
</Button>
<CreateModal
  open={open}
  onClose={() => setOpen(false)}
  onSubmit={() => api.createCustomer({ name })}
  launcherRef={launcherRef}
  title="New customer"
  isDirty={name !== ''}
  submitDisabled={name.trim() === ''}>
  <TextInput id="name" labelText="Name" value={name} onChange={...} />
</CreateModal>;
```

- `title` heads the modal and names the form; `label` (small text above the
  title) and `description` (above the form) are optional.
- `isDirty`: the app compares the field state with the initial values. When
  true, Escape, the close icon and Cancel ask "Discard changes?" first, unless
  `confirmDiscard` is false.
- `submitDisabled`: disables the primary button and Enter.
- An overlay click never closes the modal (Carbon's default for a modal
  with buttons), dirty or not.
- `launcherRef`: where focus goes on close. Without it, or when it is gone,
  focus returns to the element that had focus when the modal opened.
- `selectorPrimaryFocus`: the element focused on open. Default
  `[data-modal-primary-focus]`; without a match, the first form control.
- `size`: `sm`, `md` (default) or `lg`.
- A rejection shows `messages.error`. To show details from the
  rejection reason, set `messages.errorText` (a function, so from a client
  component). To mark fields, set `invalid` on them before rejecting: focus then goes to
  the first invalid field instead of the alert.
- `ref` and any other HTML attributes (`id`, `data-*`, `style`) go to Carbon
  Modal's root `div`, where `className` lands too. The ref is `null` while
  the modal is closed. The discard dialog renders beside it, never inside.

## Messages

`messages?: Partial<CreateModalMessages>`; defaults in
`defaultCreateModalMessages`. All strings except the optional `errorText` function, which is set
from a client component.

| Key                    | Default                                                 |
| ---------------------- | ------------------------------------------------------- |
| `create`               | Create                                                  |
| `cancel`               | Cancel                                                  |
| `pending`              | Creating                                                |
| `error`                | The changes could not be saved. Try again.              |
| `errorText`            | not set: `error` is shown                               |
| `errorIconDescription` | Error                                                   |
| `discardTitle`         | Discard changes?                                        |
| `discardBody`          | Your changes will be lost.                              |
| `discard`              | Discard                                                 |
| `keepEditing`          | Keep editing                                            |
| `leavePendingTitle`    | Stop waiting? (closing a clean form while it saves)     |
| `leavePendingBody`     | Saving continues in the background.                     |
| `leavePending`         | Stop waiting                                            |
| `keepWaiting`          | Keep waiting                                            |
| `closeIconDescription` | Close (the modal's and the discard dialog's close icon) |

## Keyboard and screen reader behaviour

On open, focus moves to the primary focus target (by default the first form
control). Focus order: the close icon, the form fields, Cancel, Create. Tab
and Shift+Tab stay inside the modal (the native dialog element makes the page
behind it inert, and `AfframeProvider` wraps Tab after Create to the close
icon).

| Key    | Where                 | Action                                                                                        |
| ------ | --------------------- | --------------------------------------------------------------------------------------------- |
| Enter  | single-line field     | Submits once, unless `submitDisabled` or a submit is pending. Not in a multi-line field.      |
| Escape | anywhere in the modal | Closes a clean modal. On a dirty one, or while a submit is pending, opens the discard dialog. |
| Escape | discard dialog        | Closes only the discard dialog; focus returns to the element that had it.                     |
| Enter  | Cancel, close icon    | Same as Escape.                                                                               |
| Tab    | discard dialog        | Moves between its close icon, Keep editing and Discard; focus starts on Keep editing.         |

On close, focus returns to `launcherRef`, else to the element that had focus
when the modal opened, else to the page body.

Screen readers announce:

- the modal as a dialog named by its title, and the form named by the title;
- while submitting, the form as busy and `pending` as a status message; the
  primary button keeps its name and shows Carbon's inline loading;
- a rejected submit as an alert with `error` (or `errorText(error)`). Focus moves to the first
  field with `aria-invalid="true"`, else to the form itself, with no focus ring, so the next
  Tab reaches the first field; the alert takes no focus;
- the discard dialog as an alert dialog named by `discardTitle`, described by
  `discardBody` (`leavePendingTitle` and `leavePendingBody` on a clean form
  while it saves).
