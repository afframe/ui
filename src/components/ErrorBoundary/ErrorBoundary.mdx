## Afframe notes

### Fallback

`ErrorBoundary` catches errors thrown while its children render and shows
`fallback` instead. Pass a full empty state as the fallback: `ErrorEmptyState`
when one region fails, `FullPageError` when the whole page fails.

The fallback appears without an announcement. Give it `role="alert"`, or move
focus to it, so screen reader users learn that the region failed:

```tsx
import { ErrorBoundary, ErrorEmptyState } from '@afframe/ui';

<ErrorBoundary
  fallback={
    <div role="alert">
      <ErrorEmptyState
        title="Invoices could not be loaded"
        subtitle="Try again in a few minutes. If it keeps failing, contact support."
      />
    </div>
  }>
  <InvoiceList />
</ErrorBoundary>;
```

### Reset

Carbon's `ErrorBoundary` has no reset function. It clears the error when its
`children` prop changes, and JSX creates new children on every render of the
parent, so any re-render of the parent renders the children again. The story's
button works this way. To reset on purpose, for example from a Try again
action, change the boundary's `key`.

It catches errors thrown while React renders, not errors in event handlers or
async code.

## ErrorBoundaryContext

`ErrorBoundaryContext` holds the `log(error, errorInfo)` function the boundary
calls when it catches an error. The default logs `errorInfo.componentStack`
with `console.log`. Provide your own to send errors to your error reporting:

```tsx
import { ErrorBoundaryContext } from '@afframe/ui';

<ErrorBoundaryContext.Provider
  value={{ log: (error, errorInfo) => trackError(error, errorInfo) }}>
  <App />
</ErrorBoundaryContext.Provider>;
```
