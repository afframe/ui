## Overview

Text inputs enable users to enter free-form text data. The type of text field
used should reflect the length of the content you expect the user to enter. The
default text input is for short, one-line content.

### Password Input

Password input is a variant of text input in its own story called
[PasswordInput](?path=/docs/components-passwordinput--overview).
It is used to collect private data and will hide the characters as a user enters
them. A user can choose to toggle on the character visibility by clicking the
view icon on the far right of the input field. When using a password input be
sure to provide detailed helper text listing any requirements related to the
data format, such as types of characters allowed or date structure.

`TextInput.Password` is deprecated, use
[PasswordInput](?path=/docs/components-passwordinput--overview)
component instead.

## Translations

When `maxCount` is set, `TextInput` announces the remaining characters to screen
readers as the value approaches the limit. These announcements can be translated
with `translateWithId`. The function receives a translation ID and an object
with `count` and `maxCount`, and must return the translated string. Use `count`
to select the correct plural form.

```jsx
const translations = {
  'carbon.text-input.counter.characters.remaining': ({ count }) =>
    count === 1 ? '1 caractère restant.' : `${count} caractères restants.`,
  'carbon.text-input.counter.characters.max-reached': () =>
    'Nombre maximal de caractères atteint.',
};

<TextInput
  id="text-input"
  labelText="Label"
  enableCounter
  maxCount={100}
  translateWithId={(id, args) => translations[id](args)}
/>;
```

| Translation ID                                     | Default                                          | `count`              |
| -------------------------------------------------- | ------------------------------------------------ | -------------------- |
| `carbon.text-input.counter.characters.remaining`   | `1 character left.` / `{count} characters left.` | Remaining characters |
| `carbon.text-input.counter.characters.max-reached` | `Maximum characters reached.`                    | `maxCount`           |

## Error message and screen readers

In Carbon 1.119, an invalid TextInput or PasswordInput points
`aria-errormessage` at its error text, but the text has no live region and no
`aria-describedby` link, so screen readers may not read it and axe reports
`aria-valid-attr-value`. Pass the error id while `invalid` is set; Carbon
renders it as `<id>-error-msg` and keeps your `aria-describedby`:

```tsx
<TextInput
  id="company-name"
  labelText="Company name"
  invalid={invalid}
  invalidText="Enter a company name."
  {...(invalid && { 'aria-describedby': 'company-name-error-msg' })}
/>
```

Set it only while `invalid` is true: otherwise it replaces the link to the
helper text. On an inline PasswordInput with helper text, Carbon overwrites it
with the helper id. A warning is linked by Carbon already.
