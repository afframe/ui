## Overview

Coachmarks
are just-in-time messages used to draw a user’s attention to a particular spot,
and explain new functionality or concepts they might not otherwise notice or
understand.

**Note:**

- The trigger element or first child of `Coachmark` should always be either a
  CoachmarkBeacon or a Button.

## When to use

Use a coachmark to point at one control the user may not notice, at the moment
it matters. Do not use it for:

- tips that stay on the page: [Guidebanner](?path=/docs/components-onboarding-guidebanner--overview);
- a welcome or announcement before the user starts: [InterstitialScreen](?path=/docs/components-onboarding-interstitialscreen--overview);
- news about features released since the last visit: [WhatsNew](?path=/docs/components-onboarding-whatsnew--overview);
- a short explanation the user opens themselves: Carbon [Toggletip](?path=/docs/components-toggletip--overview).

## Coachmark code sample

```jsx
<Theme theme="white">
  <Coachmark
    ariaLabel="Coachmark"
    position={{ x: 151, y: 200 }}
    open={isOpen}
    onClose={handleClose}
    launcherButtonRef={beaconButtonRef}
    {...args}>
    <CoachmarkBeacon
      label="Show information"
      buttonProps={{
        id: 'CoachmarkBtn',
        ref: beaconButtonRef,
        onClick: handleBeaconClick,
      }}></CoachmarkBeacon>
    <Coachmark.Content aria-label="Coachmark content" highContrast={true}>
      <Coachmark.ContentHeader
        closeIconDescription="Close"
        dragIconDescription="Drag"
        dragAriaLabel="Coachmark is being dragged"></Coachmark.ContentHeader>
      <Coachmark.ContentBody>
        <h2>Hello World</h2>
        <p>this is a description test</p>
        <Button size="sm">Done</Button>
      </Coachmark.ContentBody>
    </Coachmark.Content>
  </Coachmark>
</Theme>
```
