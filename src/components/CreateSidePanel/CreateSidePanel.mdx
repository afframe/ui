# CreateSidePanel

<SourceLabel name="afframe" />

[Source code](https://github.com/afframe/ui/tree/main/src/components/CreateSidePanel). See also [Create flows pattern](https://ibm-products.carbondesignsystem.com/?path=/docs/patterns-create-flows-createsidepanel--overview).

`CreateSidePanel` is a create form in IBM Products' `SidePanel`, for a create
task with more fields than a modal holds while the page stays in view. It
replaces IBM Products' deprecated CreateSidePanel. It shares its submit,
cancel, discard and focus behaviour with `CreateModal`, `EditSidePanel`,
`EditTearsheet` and `EditFullPage`.

## Usage and props

`open` is controlled. `onSubmit` may return a promise: while it is pending the
primary button is disabled and shows Carbon's inline loading; when it resolves, `onClose` is
called; when it rejects, the panel stays open and shows the error above the
action bar. Closing while it is pending asks first, unless `confirmDiscard` is
false: "Discard changes?" on a dirty form, "Stop waiting?" on a clean one.
Discard or Stop waiting closes the panel and ignores the result; the dialog
closes itself when the promise settles. If it is still shown or opened again
before then, it stays busy until it settles.

```tsx
import { CreateSidePanel } from '@afframe/ui';

const launcherRef = useRef<HTMLButtonElement>(null);
const [open, setOpen] = useState(false);
const [name, setName] = useState('');

<Button ref={launcherRef} onClick={() => setOpen(true)}>
  New customer
</Button>
<CreateSidePanel
  open={open}
  onClose={() => setOpen(false)}
  onSubmit={() => api.createCustomer({ name })}
  launcherRef={launcherRef}
  title="New customer"
  isDirty={name !== ''}
  submitDisabled={name.trim() === ''}>
  <TextInput id="name" labelText="Name" value={name} onChange={...} />
</CreateSidePanel>;
```

- `title` heads the panel and names it and its form; `label` (small text
  above the title, a string) and `description` (under the title) are
  optional.
- `size` (default `md`), `placement` (`right` or `left`), `slideIn` with
  `pageContentSelector` (the page content the panel pushes aside; no overlay
  then) are passed to `SidePanel`.
- `decorator`: an AI label or another decorator next to the close icon
  (`SidePanel` supports it).
- `headerSelector`: the page header the panel starts below. While open, the
  panel measures that header's bottom edge and follows its size; default
  Carbon UI Shell's `Header`. Without a header, or with it scrolled away, the
  panel is full height. The overlay stays under the header.
- `isDirty`: the app compares the field state with the initial values. When
  true, Escape, the close icon, Cancel and an overlay click ask "Discard
  changes?" first, unless `confirmDiscard` is false.
- `submitDisabled`: disables the primary button and Enter.
- `launcherRef`: where focus goes on close. Without it, or when it is gone,
  focus returns to the element that had focus when the panel opened.
- `ref` and any other HTML attributes (`id`, `data-*`, `style`) go to IBM
  SidePanel's `aside`, where `className` lands too. IBM sets `aria-label` and
  `onKeyDown` itself. The ref is `null` while the panel is closed; the discard
  dialog renders beside it, never inside.

## Messages

`messages?: Partial<CreateSidePanelMessages>`; defaults in
`defaultCreateSidePanelMessages`. All strings except the optional `errorText` function,
which is set from a client component.

| Key                    | Default                                                 |
| ---------------------- | ------------------------------------------------------- |
| `create`               | Create                                                  |
| `cancel`               | Cancel                                                  |
| `pending`              | Creating                                                |
| `error`                | The changes could not be saved. Try again.              |
| `errorText`            | not set: `error` is shown                               |
| `errorIconDescription` | Error                                                   |
| `discardTitle`         | Discard changes?                                        |
| `discardBody`          | Your changes will be lost.                              |
| `discard`              | Discard                                                 |
| `keepEditing`          | Keep editing                                            |
| `leavePendingTitle`    | Stop waiting? (closing a clean form while it saves)     |
| `leavePendingBody`     | Saving continues in the background.                     |
| `leavePending`         | Stop waiting                                            |
| `keepWaiting`          | Keep waiting                                            |
| `closeIconDescription` | Close (the panel's and the discard dialog's close icon) |

## Keyboard and screen reader behaviour

On open, focus moves to the first form control. Focus order: the close icon,
the form fields, Cancel, Create. With the overlay (the default), Tab and
Shift+Tab stay inside the panel and wrap. A `slideIn` panel has no overlay and
no trap: Tab continues into the page. Its Escape is ignored while an
open list or menu inside the panel takes it.

| Key    | Where                 | Action                                                                                                                                                              |
| ------ | --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Enter  | single-line field     | Submits once, unless `submitDisabled` or a submit is pending. Not in a multi-line field.                                                                            |
| Escape | anywhere in the panel | Closes a clean panel. On a dirty one, or while a submit is pending, opens the discard dialog.                                                                       |
| Escape | discard dialog        | Closes only the discard dialog; focus returns to the element that had it.                                                                                           |
| Tab    | discard dialog        | Moves between its close icon, Keep editing and Discard (Keep waiting and Stop waiting on a clean form while it saves); focus starts on Keep editing (Keep waiting). |

On close, focus returns to `launcherRef`, else to the element that had focus
when the panel opened, else to the page body.

A focused field never sits under the action bar: fields keep a scroll margin
the size of the bar (the test-only `FocusNotObscured` story checks it).

Screen readers announce:

- the panel as a complementary region named by `title`, and the form named
  by `title` too;
- while submitting, the form as busy and `pending` as a status message; the
  primary button keeps its name and shows Carbon's inline loading;
- a rejected submit as an alert with `error` (or `errorText(error)`). Focus moves to the first
  field with `aria-invalid="true"`, else to the form itself, with no focus ring, so the next
  Tab reaches the first field; the alert takes no focus;
- the discard dialog as an alert dialog named by `discardTitle`, described by
  `discardBody` (`leavePendingTitle` and `leavePendingBody` on a clean form
  while it saves).
